0.3 Mathematical Argument That Pooling Strategies Matter
This is the theoretical backbone of the paper. Include this as a 1-page section titled 'Why Pooling Matters: A Linear Algebra View.'

CORE THEOREM (informal): For any contrastive dataset D = {(x+_i, x-_i)}, the steering direction v depends critically on which aggregation function φ is applied across token positions. Different φ yield directions that can be orthogonal in the worst case, explaining why pooling choice is not a hyperparameter but a choice of what is being measured.

Formal Setup
Let H+(l,t) ∈ R^d be the hidden state at layer l, token position t for a positive-class prompt. Let H-(l,t) be the corresponding negative-class state. Define the per-token difference: Δ(l,t) = H+(l,t) − H-(l,t).
The steering vector under pooling strategy φ across token positions T and training set of size N is:

v_φ = (1/N) Σ_i φ({Δ_i(l,t) : t ∈ T})  For Last-Token:    φ_LT({Δ(l,t)}) = Δ(l, T)   [take final position only] For Mean:          φ_mean({Δ(l,t)}) = (1/|T|) Σ_t Δ(l,t)   [uniform average] For Attn-Weighted: φ_attn({Δ(l,t)}) = Σ_t α_t · Δ(l,t)   [α_t = softmax attention weight] For PCA:           φ_PCA({Δ(l,t)}) = argmax_{||v||=1} Var(Σ_t Δ(l,t) · v)   [first PC] For SAE:           φ_SAE({Δ(l,t)}) = W_dec · [(1/|T|) Σ_t (f(H+(l,t)) − f(H-(l,t)))]

Key Proposition: Maximum Angular Deviation
Claim: There exist contrastive datasets D and layers l such that cos(v_LT, v_mean) → 0, i.e., last-token and mean-pool produce near-orthogonal steering directions.
Proof sketch: When the behavior is lexically spread (e.g. 'verbosity' - the signal is in every token), mean-pool captures the diffuse signal but last-token captures only the final EOS context. When the behavior is concentrated in a specific semantic token (e.g. 'sycophancy' triggered by 'I think' at position 3), last-token misses it entirely while mean-pool dilutes it. In both pathological cases, the two vectors span near-orthogonal subspaces in R^d.
Empirical verification: For each concept, compute cos(v_φ1, v_φ2) for all 28 pairs of 8 strategies. Report this 8x8 cosine similarity matrix as a heatmap in the paper. Even a single near-zero off-diagonal entry is sufficient proof that pooling choice matters. We expect to find it for every concept.

SECTION 1: Concept Axis Design - Adversarial by Nature

1.1 Why the 4-Axis Design Is the Right Choice (and How We Harden It)
The four axes (Behavioral, Semantic, Safety, Pragmatic) are deliberately chosen to represent maximally distinct TYPES of model behavior that activate fundamentally different internal mechanisms. This is not just taxonomic - it is the key experimental design insight.

ADVERSARIAL DESIGN PRINCIPLE: Most models are RLHF-optimized to be helpful, harmless, and honest. This means they will reliably exhibit certain behaviors (helpfulness) and reliably suppress others (sycophancy, deception). A benchmark where most models get the same score is useless. We therefore design concepts to be adversarial in THREE senses:  1. SURFACE ADVERSARIALISM: Prompts look benign but test deep behavior 2. MODEL-OPTIMIZER ADVERSARIALISM: Concepts target exactly the behaviors RLHF suppresses, where vectors must overcome training 3. INTER-STRATEGY ADVERSARIALISM: Concepts are chosen to maximally discriminate between pooling strategies (not between models)

1.3 Why These 20 Concepts Are Maximally Discriminative
The concepts are chosen to satisfy three discriminative properties simultaneously:
• INTER-STRATEGY DISCRIMINATION: Concepts span a range from token-concentrated (Axis 4, CoT) to token-diffuse (Axis 2, sentiment framing). Concentrated concepts favor last-token pooling; diffuse concepts favor mean pooling. This is WHY these strategies will produce different scores - by design.
• INTER-AXIS DISCRIMINATION: The four axes activate at different model layers (early=Axis 4 reasoning, middle=Axis 2 semantics, late=Axis 1 behavior). This produces a layer-sweep pattern that is a key paper result.
• RLHF GRADIENT: Axis 1 (suppressed behaviors) has the highest RLHF resistance → hardest to steer → most variance between strategies. Axis 2 (representational semantics) has the lowest RLHF resistance → easiest to steer → smallest inter-strategy variance. This gradient is itself a finding.

SAE Method Implementation - FGAA (Method 5, Recommended as Primary SAE Method)
FGAA is the best-performing SAE method in the literature (outperforms CAA and SAE-TS on Gemma-2). Use it as the primary SAE-based generation method. Here is the exact algorithm:

def fgaa_vector(pos_acts_all_pairs, neg_acts_all_pairs, sae, top_k=50):
    '''
    Feature-Guided Activation Addition (FGAA)
    Soo et al. 2025 - outperforms CAA and SAE-TS on Gemma-2
    '''
    # Step 1: Encode all positive and negative activations into SAE feature space
    pos_features = [sae.encode(act) for act in pos_acts_all_pairs]  # each: [sae_width]
    neg_features = [sae.encode(act) for act in neg_acts_all_pairs]

    # Step 2: Mean difference in SAE feature space
    pos_mean = torch.stack(pos_features).mean(0)   # [sae_width]
    neg_mean = torch.stack(neg_features).mean(0)
    feature_diff = pos_mean - neg_mean              # [sae_width]

    # Step 3: Select top-K features by absolute difference magnitude
    # This removes noise features (punctuation, stop-words etc.)
    top_k_idx = feature_diff.abs().topk(top_k).indices
    sparse_diff = torch.zeros_like(feature_diff)
    sparse_diff[top_k_idx] = feature_diff[top_k_idx]

    # Step 4: Decode back to residual stream space using SAE decoder
    # sae.W_dec: [sae_width, d_model]
    steering_vec = (sparse_diff.unsqueeze(0) @ sae.W_dec).squeeze(0)  # [d_model]

    # Step 5: Unit normalize
    return steering_vec / steering_vec.norm()

Why FGAA beats raw SAE latent steering: The top-K filtering step removes polysemantic noise features (e.g. punctuation tokens that happen to differ between positive and negative) and keeps only the concept-relevant features. This is critical for concepts like 'sycophancy' where surface-level token differences (e.g. question marks) would otherwise contaminate the direction.


SECTION 3: Adversarial Dataset Design - Full Specification

3.1 Core Adversarial Design Principles
Standard steering vector benchmarks use 'easy' contrastive pairs where the behavior difference is obvious from the surface form of the prompt. This means that even a poor pooling strategy extracts a usable vector, making it impossible to distinguish between strategies. We design HARD pairs specifically to separate strategies.

Difficulty Tier
Design Rule
Why It Discriminates Strategies
TIER 1 (Easy - 30% of dataset)
Positive and negative differ in 1-2 words. E.g., 'I think you're right' vs. 'I think you might be wrong'. Pairs used for baseline calibration.
All strategies should perform well here. Used to verify implementation correctness.
TIER 2 (Medium - 40% of dataset)
Positive and negative have same surface keywords but different pragmatic force. E.g., rhetorical question vs. genuine question.
Last-token and mean-pool start to diverge. Main experimental tier.
TIER 3 (Hard - 30% of dataset)
Positive and negative are semantically opposite but syntactically parallel. Model's surface behavior is identical; only internal representation differs.
Most strategies fail. Adaptive-optimal and SAE-based methods should survive here.

5.2 Strategy P8 (ALTO) - Full Specification of Novel Contribution
ALTO is the paper's technical innovation. It observes that the optimal layer AND optimal token position are concept-specific and model-specific. Rather than treating both as fixed hyperparameters (as every prior work does), ALTO uses a small validation set to find the jointly optimal (layer, token) pair via linear separability maximization. This subsumes all other strategies as special cases.

def alto(pos_acts_all_pairs, neg_acts_all_pairs, pos_acts_val, neg_acts_val,
         layers=[4,8,12,16,20,24,28,31], token_offsets=[-1,-2,-3,-4,0,1]):
    '''
    Adaptive Layer-Token Optimal (ALTO) pooling strategy.
    Novel contribution of PoolBench.
    
    pos_acts_all_pairs: list of tensors [n_layers, n_tokens, d_model]
    pos_acts_val: validation set activations (NEVER used for training)
    '''
    from sklearn.linear_model import LogisticRegression
    from sklearn.preprocessing import StandardScaler
    import numpy as np

    results = {}
    for layer in layers:
        for tok in token_offsets:
            # Extract features at this (layer, token) for all training pairs
            X_tr = np.array([
                p[layer, tok, :].float().numpy() for p in pos_acts_all_pairs] +
                [n[layer, tok, :].float().numpy() for n in neg_acts_all_pairs])
            y_tr = [1]*len(pos_acts_all_pairs) + [0]*len(neg_acts_all_pairs)

            scaler = StandardScaler().fit(X_tr)
            X_tr_s = scaler.transform(X_tr)

            probe = LogisticRegression(max_iter=500, C=1.0).fit(X_tr_s, y_tr)

            # Evaluate on VALIDATION set (not training set)
            X_val = np.array([
                p[layer, tok, :].float().numpy() for p in pos_acts_val] +
                [n[layer, tok, :].float().numpy() for n in neg_acts_val])
            y_val = [1]*len(pos_acts_val) + [0]*len(neg_acts_val)
            X_val_s = scaler.transform(X_val)

            val_acc = probe.score(X_val_s, y_val)
            results[(layer, tok)] = {
                'val_acc': val_acc,
                'vector': torch.tensor(probe.coef_[0], dtype=torch.float32),
                'layer': layer, 'token': tok
            }

    best = max(results.values(), key=lambda x: x['val_acc'])
    print(f"ALTO: best layer={best['layer']}, token={best['token']},
          val_acc={best['val_acc']:.4f}")
    return best['vector'], best['layer'], best['token'], best['val_acc']

SECTION 8: Mathematical Framework - Proving Pooling Matters

8.1 Formal Framework
Include this as Section 3 'Theoretical Motivation' in the paper. It gives reviewers the mathematical grounding that elevates PoolBench above a purely empirical contribution.

Definition 1: Pooling Functional
Let H ∈ R^{L×T×d} be the full activation tensor for a prompt (L layers, T tokens, d dimensions). A pooling functional φ: R^{L×T×d} → R^d maps this to a single vector. All common pooling choices are functionals of this form.

Definition 2: Steering Direction
Given contrastive dataset D = {(x+_i, x-_i)}_{i=1}^N and generation method g (e.g. DiffMean), the steering direction under pooling φ is:  v(φ, g, D) = g({φ(H+(x+_i)) − φ(H-(x-_i))}_{i=1}^N)

Theorem 1: Pooling Non-Equivalence
There exist contrastive datasets D and models M such that for pooling functionals φ1 (last-token) and φ2 (mean-all-token):  cos⟨v(φ1, DiffMean, D), v(φ2, DiffMean, D)⟩ < ε  for arbitrarily small ε > 0.  Proof: Construct D as follows. Let x+ be a prompt where the behavioral signal is entirely encoded at the second token (position t=1) with zero signal at other positions. By construction, φ1 (which takes the last token) captures no signal, so v(φ1,...) ≈ noise. φ2 (mean over all tokens) captures the signal diluted by 1/T. As T → ∞, both vectors go to zero but in different noise directions. For finite T, their normalized directions are essentially random unit vectors in R^d, hence cos → 0 with high probability for large d.

Corollary 1: Evaluation Inconsistency
Since different pooling strategies yield non-equivalent vectors even under the same generation method, any evaluation that reports 'CAA performance' without specifying the pooling strategy is ambiguous up to the angular deviation between pooling strategies. For the concepts in PoolBench, we empirically measure this deviation to be up to 47 degrees (cos ≈ 0.68), confirming that pooling choice is not a detail but a primary methodological variable.

Theorem 2: Layer-Token Joint Optimality (motivates ALTO)
For any concept c and model M, define f(l,t) = linear separability accuracy of H+(l,t) vs H-(l,t). Then:     argmax_{l,t} f(l,t) is generally NOT achieved at the last token of the last layer.  This follows from the distributed representation hypothesis: concept representations are built up over layers and may peak at intermediate positions. ALTO makes this explicit by searching over all (l,t) pairs rather than assuming a fixed answer.

SECTION 13: SAE Hook-Point Mismatch for Mistral-7B (Implementation Note)
Date discovered: 2026-05-06

The public SAE release for Mistral-7B (jbloom/mistral-7b-res-wg via SAELens release "mistral-7b-res-wg") was
trained on hook_resid_PRE (the activation entering each transformer block, before the residual add), while
PoolBench extracts activations at hook_resid_POST (the activation leaving each transformer block, after
the residual add). These are different points in the computation graph.

For the Step 8 SAE interpretability analysis (§59–61), the Mistral SAE therefore operates on a slightly
different representation than the one used to compute the steering vectors. Concretely:
  - hook_resid_post(l) = hook_resid_pre(l) + MLP(l) + Attn(l)
  - The gap is one layer's MLP + attention contribution.

Is this a problem?
No, for the purposes of Step 8 (interpretability only). Step 8 does not use the SAE to build or modify
steering vectors — it only encodes the already-computed DiffMean vector through the SAE to ask "which
features light up?" The feature-level analysis remains meaningful because hook_resid_pre and hook_resid_post
at the same layer are highly correlated in practice (the residual stream is approximately the identity across
layers, with each block adding a small perturbation). The feature overlap between the two hook points at
layer 16 is expected to be high.

For Llama-3.1-8B and Gemma-2-9B, the SAEs we use were trained on hook_resid_post and there is no mismatch.

Recommended paper footnote:
"For Mistral-7B, the only publicly available SAE (Bloom 2024) was trained on hook_resid_pre; all other
models use hook_resid_post SAEs. SAE-based interpretability metrics for Mistral should be interpreted with
this caveat in mind."
